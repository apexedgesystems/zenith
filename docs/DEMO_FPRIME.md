# Demo: a stock F-prime deployment dialing into zenith

What you get: the deployment's telemetry charting live in zenith,
68 named channels decoded from a dictionary generated by the
deployment's own build. Zenith listens; the deployment dials in.
Commanding an F-prime target is not in this release; the command
pages answer with "unsupported for this protocol".

Everything below was followed as written to produce the bundled
`targets/fprime-demo` directory and the live acceptance of this
release, against framework v4.3.0.

## 1. Create the project the way the framework's own tooling does

Any Linux host with Python 3, CMake and a C++ compiler. A container
keeps the toolchain off your machine; this is the one the release
was verified with:

```dockerfile
FROM debian:bookworm-slim
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential cmake git python3 python3-pip python3-venv \
    ca-certificates && rm -rf /var/lib/apt/lists/*
WORKDIR /work
```

Run it with host networking (the deployment dials the ground system
on the host loopback) and a work directory mounted so builds persist:

```bash
docker build -t fprime-rig .
docker run -it --rm --network host -v "$PWD:/work" fprime-rig bash
```

Inside, bootstrap a project and a deployment. Accept the defaults;
the default com driver is the TCP client, which is what zenith's
listening carrier expects:

```bash
pip install fprime-bootstrap
fprime-bootstrap project          # project name: FprimeDemo
cd FprimeDemo && . fprime-venv/bin/activate
fprime-util new --deployment      # deployment name: FprimeDemoDeployment
fprime-util generate && fprime-util build
```

The build leaves two things zenith needs:

- the binary: `build-artifacts/Linux/FprimeDemoDeployment/bin/FprimeDemoDeployment`
- the dictionary: `build-artifacts/Linux/FprimeDemoDeployment/dict/FprimeDemoDeploymentTopologyDictionary.json`

## 2. Generate the zenith target directory

The converter reads the dictionary and writes the record dictionary
plus plot layouts. A spec file beside your project names the
dictionary and curates the layouts; the one that produced the
bundled directory is the shape to copy:

```json
{
  "application": "F-prime demo",
  "dictionary": "FprimeDemo/build-artifacts/Linux/FprimeDemoDeployment/dict/FprimeDemoDeploymentTopologyDictionary.json",
  "layouts": [
    {
      "name": "System",
      "plots": [
        {
          "title": "CPU load (%)",
          "channels": ["FprimeDemoDeployment.systemResources.CPU"],
          "height": 200
        },
        {
          "title": "Memory (kB)",
          "channels": [
            "FprimeDemoDeployment.systemResources.MEMORY_USED",
            "FprimeDemoDeployment.systemResources.MEMORY_TOTAL"
          ],
          "height": 200
        }
      ]
    }
  ]
}
```

```bash
python3 tools/fprime-dictgen/dictgen.py dictgen-demo.json targets/fprime-demo
```

It reports every channel it converted and every one it skipped with
the reason (strings and aggregates are stepped over on the wire, not
decoded). Rerun it after any rebuild of the deployment.

## 3. Declare the target

```toml
[[targets]]
name = "F-prime demo"
host = "127.0.0.1"                 # unused by a listening carrier
port = 50050                       # unused by a listening carrier
protocol = "tm+ccsds-spp+records"
carrier = "tcp-listen"
listen_port = 50050                # the port the deployment dials
tm_frame_size = 1024               # the framework default
auto_connect = true
records_config = "/data/targets/fprime-demo/records.json"
telemetry_config = "/data/targets/fprime-demo/telemetry.json"
```

The bundled image already carries this target and its directory, so
with the published image there is nothing to write.

## 4. Run

Start zenith first, so it is listening:

```bash
docker run -d --name zenith --network host -v zenith-data:/var/lib/zenith \
  ghcr.io/apexedgesystems/zenith:latest
```

Then the deployment, dialing the port zenith listens on:

```bash
./build-artifacts/Linux/FprimeDemoDeployment/bin/FprimeDemoDeployment -a 127.0.0.1 -p 50050
```

In zenith, the target's sidebar dot turns from amber (listening) to
green (connected) within a second, and the Telemetry page's "System"
layout charts CPU and memory. Stop the deployment and the dot
returns to amber; start it again and it reattaches on its own.

## What to expect

- 25 of the 68 channels update on an idle deployment (system
  resources, rate groups, com buffers); the rest are counters the
  framework sends only when they change.
- The dashboard shows the pipeline counters; per-component health
  cards need a command surface and are not shown for this target.
